## 1. 背景与目标

### 1.1 现状痛点

gin-vue-admin 的全部列表页都是**同构手写模板**：`gva-search-box`（内联 el-form）+ `gva-table-box`（`gva-btn-list` 按钮区 + `el-table` + `el-pagination`）+ 抽屉/弹窗编辑。每个页面都要重复维护：

- `page / pageSize / total / tableData / orderKey / desc` 六个响应式变量与四个事件回调（`onSubmit / onReset / handleSizeChange / handleCurrentChange / sortChange`）；
- 删除确认 `ElMessageBox.confirm`、删除后刷新、"末页删空回退页码"等散落在各页面的补丁逻辑（`example/customer/customer.vue` 有，多数页面没有）；
- 214 个 `el-table-column` 手写列定义，无列设置/列持久化能力；
- 表格高度不定，页面整体靠外层容器滚动，长表翻页时滚动位置丢失、操作列定位漂移；
- 行内渲染（头像、字典标签、日期格式化）逐页重复。

### 1.2 目标

| # | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 一套封装组件覆盖"查询条件 + 查询按钮 + 表格配置 + 增删改工具条 + 表格 + 分页"六件套 | 列表页模板不再出现 `el-table / el-table-column / el-pagination` |
| G2 | 封装组件与其内的表格**均自适应高度**，表格区内部滚动 | 搜索区折叠/展开、窗口 resize、keep-alive 切换后表格高度正确；翻页不丢滚动上下文（页面级） |
| G3 | 页面代码量显著下降，数据协议（page/orderKey/list 等）收敛到一处 | 典型列表页模板行数下降 ≥ 50% |
| G4 | 保留充分的逃生舱，复杂页面不被封装绑架 | 插槽可覆盖任意区域；`height` 可显式指定 |
| G5 | 视觉与现有 Element Plus 体系一致（主色跟随、暗色跟随） | 主色切换 / `html.dark` 切换实时生效 |
| G6 | 代码生成器产出新页面即用新组件 | `table.vue.tpl` / `view.vue.tpl` 改造完成，生成页通过回归 |

### 1.3 非目标（详见 [§18](#18-不做的事明确排除项)）

- 不引入 TypeScript、不引入 unplugin-auto-import（保持项目现状，减少连带改造）；
- 不替换仪表盘等**无分页/无查询**的静态小表格；
- 不做行内编辑（编辑交互维持现有 drawer/dialog 模式）。

```js
const searchInfo = ref({ username: '', nickName: '', phone: '', email: '' })
const page = ref(1); const total = ref(0); const pageSize = ref(10)
const tableData = ref([]); const orderKey = ref('id'); const desc = ref(true)

const getTableData = async () => {
  const table = await getUserList({
    page: page.value, pageSize: pageSize.value,
    orderKey: orderKey.value, desc: desc.value, ...searchInfo.value
  })
  if (table.code === 0) {
    tableData.value = table.data.list;  total.value = table.data.total
    page.value = table.data.page;       pageSize.value = table.data.pageSize
  }
}
const sortChange = ({ prop, order }) => {   // 后端排序协议
  if (prop) { orderKey.value = prop === 'ID' ? 'id' : toSQLLine(prop); desc.value = order === 'descending' }
  getTableData()
}
```

**必须吸收进封装的项目约定**：

| 约定 | 说明 | 出处 |
| --- | --- | --- |
| 请求方式 | 列表接口统一 POST，走 `@/utils/request.js`（`service`） | `@/api/user.js` 等 |
| 入参 | `{ page, pageSize, orderKey, desc, ...搜索字段 }` | 各列表页 |
| 出参 | `{ code: 0, data: { list, total, page, pageSize } }`；`code !== 0` 时 `request.js` 已全局 `ElMessage` 报错 | `@/utils/request.js` 响应拦截 |
| 行主键 | `ID`（大写）；时间字段 `CreatedAt` | 全部页面 |
| 排序协议 | `orderKey` 为蛇形（`prop === 'ID' ? 'id' : toSQLLine(prop)`），`desc` 布尔 | `sortChange` |
| 默认排序 | 大多数页面首查 `orderKey: 'id', desc: true` | 各页面初始化 |
| 全局 loading | `request.js` 对每个请求显示 `ElLoading`（target 默认 `#gva-base-load-dom`） | `@/utils/request.js` |
| 操作列宽度 | `appStore.operateMinWith`（PC '240' / mobile '80'） | `@/pinia/modules/app.js` |
| 按钮权限 | `v-auth` 指令（按 `userInfo.authorityId` 移除 DOM），按钮元数据在 `route.meta.btns` | `@/directive/auth.js`、`@/utils/btnAuth.js` |
| 字典 | `useDictionaryStore().getDictionary(type, depth)` → `[{ label, value, extend }]`（带缓存） | `@/pinia/modules/dictionary.js` |
| 导入导出 | `@/components/exportExcel` 三组件放在 `gva-btn-list` | api.vue 等页面 |

### 2.3 布局与滚动容器（自适应高度的物理约束）

`web/src/view/layout/index.vue` 的内容区结构：

```html
<div class="flex-1 w-0 h-full">
  <gva-tabs v-if="config.showTabs" />
  <div class="overflow-auto px-2" :class="config.showTabs ? 'gva-container2' : 'gva-container pt-1'">
    <router-view v-slot="{ Component, route }">
      <div id="gva-base-load-dom" class="gva-body-h bg-gray-50 dark:bg-slate-800">
        <keep-alive :include="routerStore.keepAliveRouters">
          <component :is="Component" :key="route.fullPath" />
        </keep-alive>
      </div>
    </router-view>
    <BottomInfo />
  </div>
</div>
```

关键事实：

- `#app { height: 100vh; overflow: hidden }`，**页面滚动不发生在 window**，发生在中间层 `div.overflow-auto`；
- 该滚动容器有**确定高度**：`.gva-container { height: calc(100% - 2.5rem) }`、`.gva-container2 { height: calc(100% - 4.5rem) }`（见 `web/src/style/main.scss` 与 `element_visiable.scss`）；
- 其内层的 `.gva-body-h` 只有 `min-height: calc(100% - 3rem)` —— **min-height 不构成百分比高度链**，页面内容可以无限撑高由外层滚动；
- `BottomInfo` 是滚动容器尾部的兄弟节点；
- keep-alive 缓存页面（`routerStore.keepAliveRouters`），切换标签页回来时不重新挂载。

**推论**：表格组件想"自适应高度"，不能简单 `height: 100%`（父级 `.gva-body-h` 无确定高度），要么改布局（影响所有未迁移页面，不可行），要么**相对滚动容器做测量**——本设计采用后者（见 [§13](#13-自适应高度设计重点)）。

### 2.4 其他相关事实

- 全站 `<script setup>` + `defineOptions({ name })`；**无** unplugin-auto-import / unplugin-vue-components；Element Plus 全量注册（`app.use(ElementPlus)`）；el-icons 全局注册；UnoCSS（preset-wind3）原子类；
- 路由 = 静态路由 + 后端菜单动态路由（`asyncMenu`），`createWebHashHistory`；
- 暗色模式：`html.dark` class（`useDark`），页面配色大量 `dark:bg-slate-900` 系；
- Element 主色运行时可变：`utils/format.js#setBodyPrimaryColor` 修改 `--el-color-primary`（存 `appStore.config.primaryColor`）；
- `web/src/style/element_visiable.scss` 对 `.el-table th/td` 行高（36/32px）、`.el-pagination`、`.el-form--inline .el-form-item > *`（固定 `w-52`）做了全局覆写——**对 vxe 组件无效**，vxe 侧需另行统一；
- 代码生成器模板同样内嵌这套模式：`server/resource/package/web/view/table.vue.tpl`、`server/resource/plugin/web/view/view.vue.tpl`；
- Vite 8（rolldown-vite，构建配置用 `rolldownOptions`）。

## 3. 技术选型

### 3.1 为什么是 vxe-grid（而非继续封装 el-table 或换其它库）

- 一体化：`vxe-grid` 单组件原生集成 **表单（查询区）+ 工具栏 + 表格 + 分页 + 数据代理（proxyConfig）**，与本任务"六件套"需求一一对应，无需自己拼装布局与联动；
- 成熟度：虚拟滚动、树表格、列拖拽、列设置持久化、全屏（zoom）、单元格渲染器体系都是内置能力，这正是 el-table 封装需要长期自研的部分；
- 可定制：v4 全 CSS 变量驱动（`--vxe-ui-*`），主色/暗色可映射到 Element 体系；
- 生态参考：vben-admin v5 即采用"vxe-table + 适配层"方案，架构有成熟先例可对标。

### 3.2 依赖与版本

| 包 | 版本 | 说明 |
| --- | --- | --- |
| `vxe-table` | `~4.21.5` | 表格/网格核心（含 `vxe-grid`）。官方建议用 `~` 锁版本，避免非兼容更新 |
| `vxe-pc-ui` | `~4.17.29` | 基础组件库（v4.7+ 从 vxe-table 拆出：按钮、输入框、分页、弹窗、表单渲染器 `$input/$select/$datepicker` 等），`vxe-grid` 的 form/toolbar/pager 依赖它 |

> 版本为官方当前推荐组合（2026-09 查证）。实施时以 `https://vxetable.cn` 首页推荐为准微调，**必须两包同批升级**。
> 注意：v4.0.x ~ v4.6.x 已于 2024-12 停止维护，不要降级使用。

### 3.3 引入方式

与项目 Element Plus"全量引入"的策略保持一致（降低首期复杂度，按需引入列为后续优化项，见开发计划 M3）：

```js
// web/src/main.js（新增）
import VxeUIAll from 'vxe-pc-ui'
import 'vxe-pc-ui/lib/style.css'
import VxeUITable from 'vxe-table'
import 'vxe-table/lib/style.css'

app.use(VxeUIAll).use(VxeUITable)
```

主题定制样式在 `web/src/components/gvaGrid/style/index.scss` 中通过 CSS 变量完成（见 [§14](#14-主题与暗色适配)），**不使用 scss 变量重编译**，避免与 Element 的运行时换色机制冲突。

### 3.4 对 vben-admin 的借鉴与差异

| vben-admin v5 | 本设计（GvaGrid） | 差异原因 |
| --- | --- | --- |
| `useVbenVxeGrid({ gridOptions, gridEvents, formOptions })` | `useGvaGrid({ api, columns, searchItems, ... })` | 我们把 gin-vue-admin 后端协议（page/orderKey/desc、list/total）做进 hook 的 proxyConfig 适配器，页面少写协议代码 |
| BasicTable 组件 + formProps 独立渲染 | `GvaGrid` 薄壳 + vxe-grid 原生 `formConfig` | vxe 原生 form 与 proxy/高度联动更完整，减少自研 |
| 自研 adapter-vxe-table 全局渲染器 | `renderers.js` 注册 `gva*` 系列渲染器（字典/日期/头像/操作列） | 同思路，接 gin-vue-admin 的字典 store 与 el-button 体系 |
| TS + auto-import | JS + 手动 import | 保持项目现状，控制改造半径 |

## 4. 总体架构

### 4.1 分层图

```
┌────────────────────────────────────────────────────────────────────┐
│  页面层  user.vue / api.vue / ……（24 个列表页）                       │
│    useGvaGrid({ api, columns, searchItems, defaultSort, … })        │
│    <GvaGrid v-bind="gridOptions" v-on="gridEvents">                 │
│      #toolbar-buttons（增删改按钮，v-auth）                          │
│      #xxx 单元格插槽（逃生舱）                                        │
│    </GvaGrid> + el-drawer 编辑抽屉（不变）                            │
└───────────────┬────────────────────────────────────────────────────┘
                │ gridOptions / gridEvents / 插槽透传
┌───────────────▼────────────────────────────────────────────────────┐
│  薄壳组件层  GvaGrid（web/src/components/gvaGrid/index.vue）          │
│    · 卡片外观（对齐 gva-table-box 视觉）                              │
│    · 高度自适应（useGridHeight 测量 → .gva-grid 定高 → grid height:auto）│
│    · $slots 全量透传给 vxe-grid                                       │
│    · 列个性化/密度/全屏等表格配置入口                                   │
└───────────────┬────────────────────────────────────────────────────┘
                │ vxe-grid 原生配置
┌───────────────▼────────────────────────────────────────────────────┐
│  vxe-grid（vxe-table 4.21）                                          │
│    ┌ formConfig    查询条件 + 查询/重置按钮（vxe-pc-ui 渲染器）        │
│    ├ toolbarConfig 左：#toolbar-buttons 增删改；右：刷新/密度/列设置/全屏 │
│    ├ table         列 schema → columns；排序/选择/虚拟滚动/单元格渲染器  │
│    ├ pagerConfig   TotalLayout/Sizes/… 对齐现有 el-pagination 布局     │
│    └ proxyConfig   ajax.query 适配 gin-vue-admin 协议（↓）             │
└───────────────┬────────────────────────────────────────────────────┘
                │ { page, pageSize, orderKey, desc, ...form } → POST
┌───────────────▼────────────────────────────────────────────────────┐
│  @/api/*.js → @/utils/request.js → gin-vue-admin 后端                │
│            ← { code: 0, data: { list, total, page, pageSize } }      │
└────────────────────────────────────────────────────────────────────┘
```

### 4.2 一次查询的完整链路（时序）

```
用户点击"查询"按钮
 → vxe formConfig 提交（校验通过）
 → vxe-grid commitProxy('reload')            // 重置到第 1 页
 → proxyConfig.ajax.query({ page, sorts, form })
 → useGvaGrid 适配器组装 { page, pageSize, orderKey, desc, ...form }
 → api(params)（request.js，loadingOption:false → 用 vxe 表格自带遮罩）
 → { code, data } → 适配器归一化为 { result, total }
 → vxe-grid 渲染表格 + 分页
```

翻页/改每页条数/点排序表头：同链路，`commitProxy` 类型分别为页码查询/排序查询（`sorts` 参数变化），页码不重置。

## 6. useGvaGrid —— 配置与数据适配层

对标 vben 的 `useVbenVxeGrid`。**页面的全部诉求通过一个 options 对象声明**，hook 产出可直接绑定到 `<GvaGrid>` 的配置与事件。

### 6.1 Options

```js
useGvaGrid({
  /* ---- 标识 ---- */
  id: 'superAdmin-user',        // 可选。列设置持久化（localStorage）key；建议 `模块-页面`

  /* ---- 数据 ---- */
  api: getUserList,             // 必填。(params) => Promise<{code, data:{list,total}}>，见 §12
  beforeQuery: (params) => {},  // 可选。最后机会修改出参（追加隐藏条件、改字段名）
  afterQuery: (res) => {},      // 可选。响应后处理（副作用：回填合计数等）

  /* ---- 列 ---- */
  columns: [ … ],               // 必填。GVA 列 schema，见 §10.2
  operateWidth: undefined,      // 可选。操作列宽度，默认取 appStore.operateMinWith

  /* ---- 查询区 ---- */
  searchItems: [ … ],           // 可选。查询条件 schema，见 §8.2；不传则不渲染查询区
  searchDefaults: {},           // 可选。初始/重置值（含隐藏查询条件）
  searchCollapse: 3,            // 可选。超过 N 项自动折叠（collapseNode），默认不折叠

  /* ---- 排序 ---- */
  defaultSort: { field: 'ID', order: 'desc' },  // 默认 { field:'ID', order:'desc' }；传 null 关闭

  /* ---- 行为 ---- */
  checkbox: false,              // true 时自动追加首列复选列（翻页保留选择）
  pageSize: 10,
  pageSizes: [10, 30, 50, 100],
  autoLoad: true,               // 挂载即查询；keep-alive 切回不重查（与现状一致）
  keepSelection: true,          // checkboxConfig.reserve，跨页保留

  /* ---- 高度 ---- */
  height: 'fit',                // 'fit' | number | 'auto'，见 §13；弹窗内建议传具体数值

  /* ---- 透传 ---- */
  gridConfig: { … }             // 原样 merge 进 vxe-grid 的 v-bind（逃生舱，任意原生配置）
})
```

### 6.2 返回值

| 返回 | 类型 | 说明 |
| --- | --- | --- |
| `gridRef` | `ref` | 绑到 `<GvaGrid ref="gridRef">`，可调用 vxe-grid 全部实例方法（`getCheckboxRecords()` 等） |
| `gridOptions` | `object` | 绑到 `<GvaGrid v-bind="gridOptions">` 的完整 vxe-grid 配置 |
| `gridEvents` | `object` | 绑到 `v-on`：`checkbox-all/checkbox-change/sort-change/cell-click/…` 原生透传 + 封装内聚事件 |
| `reload()` | `fn` | 回到第 1 页重新查询（增删改成功后调用；对齐现有"保存后 getTableData()"语义按需选择） |
| `refresh()` | `fn` | 保持当前页/条件重新查询 |
| `getFormData()` / `setFormData(patch)` | `fn` | 读写当前查询条件（编程式查询） |
| `selectedRows` | `ref` | 已勾选行（`checkbox` 模式；聚合 `checkbox-change/checkbox-all` 事件） |
| `clearSelection()` | `fn` | 清空勾选 |

### 6.3 与删除/批量删除的配合（useGvaGridDelete）

```js
const { onBatchDelete, onDelete } = useGvaGridDelete(gridRef, {
  delete: (rows) => deleteUser({ id: rows.map((r) => r.ID).join(',') }), // 按现有接口约定
  confirmText: '确定要删除吗',      // 默认对齐现有 ElMessageBox 文案
  successText: '删除成功'

```

内部行为：`ElMessageBox.confirm`（type: warning，文案对齐现状）→ 调 `delete` → 成功 `ElMessage.success` → `refresh()`（适配器含空页回退，见 §12.4）→ `clearSelection()`。删除失败不弹成功、不刷新（`request.js` 已负责错误提示）。

## 7. GvaGrid —— 薄壳组件

### 7.1 Props

| prop | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `height` | `String \| Number` | `'fit'` | 见 §13：`'fit'` 测量填充 / 数值(px) 固定 / `'auto'` 填充有确定高度的父级 |
| `bottomReserve` | `Number` | `56` | fit 模式底部预留（BottomInfo 高度 + 容器 padding），可按页面微调 |

其余（`columns/formConfig/toolbarConfig/pagerConfig/proxyConfig/…`）**全部透传**给 `vxe-grid`（由 `gridOptions` 经 `v-bind` 传入），GvaGrid 不复制 vxe 的 props 面。

### 7.2 Slots（全部转发给 vxe-grid）

| slot | 落点 | 用途 |
| --- | --- | --- |
| `toolbar-buttons` | `toolbarConfig.slots.buttons`（左） | 增/删/导出导入等业务按钮，可继续用 `el-button`、`v-auth`、`ExportExcel` |

| `form-xxx` | 查询项 `itemRender` 为 `{ name: 'slot' }` 时的插槽 | 单个复杂查询条件（如远程搜索、级联） |
| `xxx`（任意列名） | 列 `slots: { default: 'xxx' }` | 单元格内容（头像、标签、按钮组…），作用域含 `{ row, rowIndex, column }` |
| `xxx-header` | 列 `slots: { header: 'xxx-header' }` | 自定义表头 |
| `empty` | 表格空数据 | 自定义空态 |
| `pager-extra` | 分页区左侧 | 少见需求（如分页旁提示文案） |

实现要点（标准透传模式）：

```html

<template>
  <div ref="wrapRef" class="gva-grid" :class="{ 'gva-grid--fit': isFit }" :style="fitStyle">

      <template v-for="(_, name) in $slots" :key="name" #[name]="scope">

      </template>
    </vxe-grid>
  </div>
</template>
```

## 8. 查询区（查询条件 + 查询按钮）设计

### 8.1 结构与行为

查询区使用 **vxe-grid 原生 `formConfig`**（渲染在 grid 内部，参与自适应高度布局，不额外占卡片）：

- 查询/重置按钮由 vxe 自动生成（`formConfig` 提交触发 `proxyConfig` 查询，重置清空后自动重查），文案统一配置为「查询」「重置」，按钮类型对齐现有视觉（primary + 默认）；
- 默认行为对齐现有页面语义：**查询 = 回到第 1 页**（`reload`），**重置 = 清空条件 + 恢复 `searchDefaults` + 回到第 1 页**；
- 条件较多时支持折叠（`searchCollapse` 控制，超出部分默认隐藏，「展开/收起」切换）。

### 8.2 查询项 schema（searchItems）

```js
searchItems: [
  // 文本：vxe-pc-ui 内置渲染器
  { field: 'username', title: '用户名', itemRender: { name: '$input', props: { placeholder: '用户名', clearable: true } } },
  // 下拉（静态选项）
  { field: 'method', title: '请求', itemRender: { name: '$select', props: { placeholder: '选择', clearable: true, options: [
    { label: 'GET', value: 'GET' }, { label: 'POST', value: 'POST' }
  ] } } },
  // 字典下拉（自定义渲染器，走 pinia dictionary store，自动缓存）
  { field: 'authorityId', title: '角色', itemRender: { name: 'gvaDictSelect', props: { dict: 'authority', depth: 1 } } },
  // 日期范围（出参自动拆 start/end，见 props 处理）
  { field: 'createdAt', title: '创建时间', itemRender: { name: 'gvaDateRange' } },
  // 复杂条件 → 插槽逃生舱（可放 el-cascader、远程搜索 el-select 等）
  { field: 'apiPath', title: '路径', itemRender: { name: 'slot' } }
  // 对应模板：<template #form-apiPath="{ data }"><el-input v-model="data.apiPath" /></template>
]
```

设计原则：**80% 常用条件零模板代码**（`$input/$select/gvaDictSelect/gvaDateRange` 覆盖现状全部 17 个页面的查询条件类型），**20% 复杂条件走插槽**继续用 Element Plus 组件，不做大而全的渲染器。

### 8.3 自定义查询渲染器清单（renderers.js 注册）

| name | 功能 | 说明 |
| --- | --- | --- |
| `gvaDictSelect` | 字典下拉 | `props: { dict: 类型, depth: 1 }`；异步 `getDictionary` 后渲染 options；label/value 对齐 store 结构 |
| `gvaDateRange` | 日期范围 | 基于 `$datepicker` range；`props.mapField: ['start', 'end']` 控制出参拆分 |
| `slot` | 插槽占位 | itemRender 通用约定，由 GvaGrid 的插槽透传承接 |

> 实现注记：vxe form 渲染器经 `VxeUI.renderer.add('name', { renderFormItem(opts, { data }, context) {} })` 注册（vxe-pc-ui 导出 `VxeUI`）；插槽承接需在 `formConfig.items` 上生成 `slots: { default: 'form-xxx' }`（以锁定版本 4.21.x 的官方文档为准校对字段名，见 §19 风险 R7）。

### 10.4 排序协议适配（hook 内聚）

```js
// vxe sorts: [{ field, order: 'asc' | 'desc' | null }]
function toOrderParams(sorts, defaultSort) {
  const s = sorts && sorts.length ? sorts[0] : null
  if (!s || !s.order) {
    return defaultSort
      ? { orderKey: defaultSort.field === 'ID' ? 'id' : toSQLLine(defaultSort.field), desc: defaultSort.order !== 'asc' }
      : {}                                     // 页面声明 defaultSort: null 时交由后端默认
  }
  return { orderKey: s.field === 'ID' ? 'id' : toSQLLine(s.field), desc: s.order !== 'asc' }
}
```

（`toSQLLine` 来自 `@/utils/stringFun.js`，驼峰 → 蛇形，与现有 `sortChange` 逻辑逐字对齐。）

## 12. 数据代理层设计（useGvaGridProxy）

### 12.1 proxyConfig 总装

```js
proxyConfig: {
  form: true,                          // 自动收集 formConfig 数据并注入 query 的 form
  props: { result: 'result', total: 'total' },
  autoLoad: options.autoLoad !== false,
  ajax: {
    query: queryAdapter(options),      // 见 12.2
    // delete/save 不使用 vxe 内置 CRUD 代理（保持现有 ElMessageBox + drawer 交互），
    // 增删改统一走 §6.3 的 useGvaGridDelete 与页面自身逻辑
  }
}
```

### 12.2 query 适配器（协议核心）

```js
async function queryAdapter({ page, sorts, form }) {
  const params = {
    page: page.currentPage,
    pageSize: page.pageSize,
    ...form,                                  // 搜索字段平铺（对齐现有 ...searchInfo）
    ...toOrderParams(sorts, options.defaultSort)
  }
  options.beforeQuery?.(params)

  const res = await options.api({ ...params, loadingOption: false })  // 见 12.5

  if (res.code !== 0) return { result: [], total: 0 }   // 错误提示已由 request.js 全局处理
  const data = res.data || {}
  options.afterQuery?.(res)

  // 空页回退（吸收 customer.vue 的补丁逻辑，统一全站行为）
  if (autoFixEmptyPage && page.currentPage > 1 && (!data.list || !data.list.length)) {
    return refetchPrevPage(params)            // 以 page-1 重查一次并同步回 grid 分页状态
  }
  return { result: data.list || [], total: data.total || 0 }
}
```

### 12.3 出入参对照表

| vxe 侧 | 后端协议 | 备注 |
| --- | --- | --- |
| `page.currentPage` | `page` | int |
| `page.pageSize` | `pageSize` | int |
| `sorts[0]` | `orderKey`（蛇形）+ `desc`（bool） | §10.4 |
| `form` | 逐字段平铺 | 日期范围经 `gvaDateRange.mapField` 拆分 |
| 返回 `{ result, total }` | `data.list / data.total` | code!==0 → 空 result |

### 12.4 空页回退（末页删空）

现状仅 `customer.vue` 处理了"删除后末页为空回退页码"。统一方案：query 适配器检测"当前页 > 1 且结果为空"时以 `page - 1` 重查（最多回退一次），并同步 grid 的 pager 页码（通过 `gridRef` 的分页实例或再次 `commitProxy`）。若实施时确认 vxe 4.21 的 proxy 已内置等价行为（官方在 query 空结果时有自动翻页修正逻辑，需实测确认），则删除自定义实现，保留行为测试。

### 12.5 全局 loading 协调

现状 `request.js` 对每个请求显示全局 `ElLoading`（target 默认 `#gva-base-load-dom`），而 vxe-grid 在 proxy 查询期间会显示**表格区自带遮罩**，两者叠加造成双遮罩闪烁。

方案（M0 任务，加法改动、向后兼容）：

```js
// @/utils/request.js 拦截器中（伪码）
if (config.loadingOption === false) {   // 新增：显式关闭全局 loading 的逃逸口
  return config
}
showLoading(config.loadingOption)
```

useGvaGrid 的所有请求默认带 `loadingOption: false`，加载态交给 vxe 表格遮罩（区域更精准）。页面内非表格请求不受影响。

## 13. 自适应高度设计（重点）

### 13.1 需求与约束回顾

- 需求：**封装组件（含查询区/工具栏/分页的整卡）与表格本体都自适应高度**——即列表页在视口内整屏呈现，表格数据区内部滚动，翻页不改变页面滚动位置；
- 约束（§2.3）：页面滚动容器是 layout 的 `div.overflow-auto`（有确定高度），但其内层 `.gva-body-h` 是 `min-height`（无确定高度），`height: 100%` 链条断掉；`BottomInfo` 是滚动容器尾部兄弟；不能全局改布局（未迁移页面共存期长达数周）。

### 13.2 方案：测量式 fit + 多级降级

**模式一 `fit`（默认，列表页）**：GvaGrid 根元素 `.gva-grid` 的高度由 `useGridHeight` 实时测量得出：

```
组件高度 = 滚动容器 clientHeight
         − (GvaGrid 顶边相对滚动容器顶边的距离)   ← getBoundingClientRect().top 差值
         − bottomReserve(默认 56px = 容器底部 padding + BottomInfo)
```

`.gva-grid { display: flex; flex-direction: column; }` → 内部 `<vxe-grid height="auto">` 填满组件高度（vxe 官方的父级填充模式：**父容器需有确定高度，且 vxe-grid 为其唯一子节点**——本结构天然满足）。vxe-grid 内部自行分配：查询区/工具栏/分页取自然高度，**表格区 flex 撑满剩余空间并内部滚动**。查询区折叠/展开、工具栏换行、分页换行时 vxe 自动重算表格区高度。

测量时机（全部触发 `compute()`，rAF 节流合并）：

| 时机 | 手段 |
| --- | --- |
| 首次挂载 | `onMounted` + `nextTick`（transition 场景二次延迟 240ms 复算兜底） |
| 滚动容器尺寸变化 | `ResizeObserver.observe(容器)`（侧栏折叠、窗口 resize、移动端旋转全覆盖） |
| keep-alive 切回 | `onActivated`（页面缓存的 DOM 尺寸可能已变） |
| 测量保护 | 结果 `< 240px` 时钳制为 240px（防止抽屉/异常布局压扁表格） |

**模式二 显式高度**：`height` 传数值（px）→ 直接作为 vxe-grid 高度。用于**抽屉/弹窗内嵌表格**（如 `authority/components/menus.vue`）与特殊布局页。

**模式三 `auto`**：传 `'auto'` → vxe-grid 填充"已有确定高度的父级"。用于页面自行控制布局的场景。

**降级**：`fit` 模式下找不到滚动容器（如全屏遮罩内、单测环境）→ 自动降级为 `max-height: calc(100vh - 240px)` + `console.warn('[GvaGrid] fit 容器未找到，已降级为 max-height 模式')`，保证功能可用。

### 13.3 useGridHeight 骨架

```js
// hooks/useGridHeight.js
import { ref, onMounted, onActivated, onBeforeUnmount, nextTick } from 'vue'

export function useGridHeight({ selector, bottomReserve = 56, min = 240 } = {}) {
  const wrapRef = ref(null)
  const height = ref(0)          // 0 表示测量失败（触发降级）
  let ro = null
  let rafId = null

  const compute = () => {
    if (rafId) cancelAnimationFrame(rafId)
    rafId = requestAnimationFrame(() => {
      const el = wrapRef.value
      if (!el) return
      const container = el.closest(selector)
      if (!container) { height.value = 0; return }
      const occupied = el.getBoundingClientRect().top - container.getBoundingClientRect().top
      height.value = Math.max(container.clientHeight - occupied - bottomReserve, min)
    })
  }

  onMounted(async () => {
    await nextTick()
    compute()
    setTimeout(compute, 240)                       // 路由 transition 结束后复算兜底
    const container = wrapRef.value?.closest(selector)
    if (container && 'ResizeObserver' in window) {
      ro = new ResizeObserver(compute)
      ro.observe(container)
    }
    window.addEventListener('resize', compute)
  })
  onActivated(() => nextTick(compute))             // keep-alive
  onBeforeUnmount(() => {
    ro?.disconnect()
    window.removeEventListener('resize', compute)
    if (rafId) cancelAnimationFrame(rafId)
  })

  return { wrapRef, height }
}
```

GvaGrid 内：

```js
const isFit = props.height === 'fit'
const { wrapRef, height } = useGridHeight({ selector: props.fitContainerSelector, bottomReserve: props.bottomReserve })
const fitStyle = computed(() => (isFit && height.value ? { height: `${height.value}px` } : {}))
const innerHeight = computed(() => {
  if (isFit) return height.value ? 'auto' : undefined   // 降级时交给 scss 的 max-height
  return typeof props.height === 'number' ? props.height : props.height
})
```

## 17. 代码生成器模板同步方案

autoCode 生成的新页面必须直接产出 GvaGrid 用法，否则迁移成果会被生成器稀释。涉及两个 Go 模板：

| 模板 | 作用 |
| --- | --- |
| `server/resource/package/web/view/table.vue.tpl` | autoCode 生成业务包的列表页 |
| `server/resource/plugin/web/view/view.vue.tpl` | 插件包前端页面 |

改造要点（以 table.vue.tpl 为例）：

- `{{range .Fields}}` 循环产出列 schema：文本列 `{ field: "{{.FieldJson}}", title: "{{.FieldDesc}}", minWidth: {{.Width}} }`；日期列追加 `cellRender: { name: 'gvaDate' }`；可搜索字段产出对应 `searchItems`（字段类型 → 渲染器映射：string→`$input`、bool→`gvaDictSelect`/`$select`、time→`gvaDateRange`、富文本/图片/关联不进搜索）；
- `{{ if .IsTree }}` 分支产出 `treeConfig`；
- 保留生成物的 drawer 表单不动（`form.vue.tpl` 不变）；
- 预览链路（autoCode 在线预览）用同一模板，改完即可在管理界面验证生成效果。

验收方式：用生成器新建"测试书册表（含字符串/数字/布尔/时间/图片字段）"，检查生成页面开箱即用（查询/分页/排序/增删改/自适应高度全通）。

## 21. 实现注记（2026-09-05 实施后回写，R7 关闭）

以下为实施过程中对照 vxe-table@4.21.5 / vxe-pc-ui@4.17.30 实际源码校验出的差异与最终实现口径（均已落地在 `web/src/components/gvaGrid/`）：

| # | 设计文档原口径 | 实际实现 | 原因 |
| --- | --- | --- | --- |
| 1 | pager `layouts: ['TotalLayout', 'SizesLayout', …]` | `['Total','Sizes','PrevJump','PrevPage','Number','NextPage','NextJump','FullJump']` | pager 只识别无 Layout 后缀的名称（源码 switch-case 核实） |
| 2 | proxyConfig 用 `props: { result, total }` | 必须用 `response: { result: 'result', total: 'total' }` | vxe 全局默认注入 `response`（total 默认 `page.total`），`response || props` 恒取 response，`props` 永远失效 |
| 3 | §14 手工映射 `--vxe-ui-*` 背景变量到 Element | 改用 **vxe 内置主题**：`VxeUI.setTheme('dark'|'light')` 写入 `data-vxe-ui-theme` 属性，GvaGrid 用 MutationObserver 监听 `html.dark` 自动同步；仅保留 `--vxe-ui-primary-color: var(--el-color-primary)` 主色桥接 + 行高尺寸变量 | 内置暗色主题覆盖 122 个变量，手工映射不可维护；且 `.gva-grid` 作用域变量声明会遮蔽 `html.dark` 全局覆盖 |
| 4 | 表单折叠 `collapseNode` 语义 | item 级 `collapseNode: true` 标记触发节点；`collapseStatus: true` = 折叠态（与直觉相反）；GvaGrid 通过响应式覆盖 `formConfig.collapseStatus` 控制展开收起 | 源码 `folding && collapseAll` 隐藏逻辑核实 |
| 5 | 工具栏刷新「保持当前页」 | `toolbarConfig.refresh: { code: 'query' }`（默认 `reload` 会回第 1 页） | commitProxy `query` 与 `reload` 的分页行为差异 |
| 6 | 列设置持久化 key `gva-grid-custom:{id}` | vxe 统一存于 `VXE_CUSTOM_STORE`，以 grid `id` 为子键；开启 storage 时**每个数据列必须有 field**，操作列由 schema 归一化自动补 `field: 'operate'` | vxe `getCustomStorageMap(tableId)` 实现 |
| 7 | 空页回退自研 | vxe 内置「超出最大页钳制」，叠加自研回退：`ajax.querySuccess` 中检测空结果 + `setCurrentPage(n-1)` + `commitProxy('query')` | 两者互补：钳制只修页码显示，回退才重查数据（冒烟测试验证） |
| 8 | 查询/重置按钮由 vxe 生成（`$buttons` 渲染器，已废弃） | GvaGrid 内部插槽 `#gva-form-buttons` 渲染 **Element 按钮**，经 `provide/inject` 自动调用 useGvaGrid 的 `submitSearch/resetSearch`；重置 = 清条件 + 恢复 searchDefaults + clearSort + 回第 1 页 | 视觉一致性（R1）；`$buttons` 已标记 deprecated；重置语义完全对齐旧页面 onReset |
| 9 | 查询项渲染器钩子 `renderFormItem` | 实际钩子名 `renderFormItemContent`（单元格 `renderTableDefault`、重置 `formItemResetMethod`） | vxe-pc-ui form/src/render.js 核实 |
| 10 | 排序协议仅 orderKey/desc | 新增 `sortProtocol: 'gva'(默认) \| 'autoCode'`；代码生成器后端为 `{ sort: 蛇形列名, order: 'ascending'\|'descending' }` | autocode 生成页 `request.go.tpl` 的 Sort/Order 字段核实 |
| 11 | 全局 loading 逃逸口 `loadingOption: false` | 已实现：request.js 请求拦截器检测 `config.data.loadingOption === false` 后跳过 ElLoading 并**从请求体剔除该键**（不污染后端参数） | 无法穿透页面 api 函数传 axios config，故走请求体内联 + 剔除方案 |
| 12 | 表格数据后处理（如 user.vue 的 authorityIds 回填） | `useGvaGrid({ afterQuery(res) })` 钩子，直接改 `res.data.list` | 原 watch(tableData) 模式在代理模式下不可用 |
| 13 | 动态下拉选项传入 searchItems | 传 `reactive([])` 空数组并在加载后原地 splice 填充（传 `.value` 快照不会更新） | vxe options prop 不支持 Ref |
| 14 | gvaDateRange 出参拆分 | 声明 `props.startField/endField` 时由 proxy 适配器在提交前自动拆分并删除原数组字段（time BETWEEN 的 `xxxRange` 数组出参不拆分，与生成器后端约定一致） | 覆盖 sysParams/exportTemplate/announcement 及生成页 |
