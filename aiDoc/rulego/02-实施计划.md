## M2 桥接运行（约 1 天）

> 评审修订要点：① 构造失败**降级不 panic**（Register 在 InstallPlugin 回调内执行，panic 会杀死 GVA 进程）；② **M2 起即设 `require_auth=true`**（默认 false 时匿名请求以默认 admin 放行，绝不可裸奔到 M3）；③ 挂载点加 **x-token → Authorization 头映射中间件**（rulego 不识别 `x-token`，此中间件 M2 就位、M3 直接受益）；④ **生命周期自闭环**（GVA v2 插件接口无 Stop 钩子，胶水层自订阅退出信号）。

### 2.1 胶水插件骨架

`server/plugin/rulego/plugin.go`（沿用 GVA 插件形态，示例骨架，字段以实际 API 为准）：

```go
package rulego

import (
    "os"
    "os/signal"
    "syscall"

    "github.com/flipped-aurora/gin-vue-admin/server/global"
    interfaces "github.com/flipped-aurora/gin-vue-admin/server/utils/plugin/v2"
    "github.com/gin-gonic/gin"
    "github.com/rulego/rulego/server/app"
    "github.com/rulego/rulego/server/bootstrap"
    "github.com/rulego/rulego/server/bridge"
    "go.uber.org/zap"
)

const prefix = "/rulego"

var App *app.App

type plugin struct{}

var Plugin = new(plugin)

func init() { interfaces.Register(Plugin) } // utils/plugin/v2 注册（同 announcement 插件形态）

func (p *plugin) Register(group *gin.Engine) {
    // 注意：经 InstallPlugin 调用；GVA_DB 未初始化时会延迟到 DB 就绪回调后才执行到这里
    // （rulego 不依赖 GVA DB，接受该时序；GVA 完成 init 后即恢复即时注册）
    cfg := loadConfig() // 读取 server/resource/rulego/config.conf；必须含 require_auth=true（见 2.2）
    b, err := bridge.New(
        bridge.WithAppOptions(
            app.WithConfig(cfg),                              // BasePath: "/rulego"
            app.WithModules(bootstrap.DefaultModules()...),
            // M3 追加: app.WithAuthenticator / app.WithAuthorizer（见 3.1，实现须对齐 §4.6 设计）
        ),
        // M3 追加: bridge.WithoutLocalAuth()——其硬约束 RequireAuth=true 在 M2 已满足
        bridge.WithResponseWrapper(gvaEnvelope),              // 统一 {code,data,msg} 信封
    )
    if err != nil {
        // 降级：规则引擎是增强能力，构造失败只告警、不挂路由，GVA 主功能不受影响（勿 panic）
        global.GVA_LOG.Error("rulego bridge 初始化失败，/rulego/** 不可用", zap.Error(err))
        return
    }
    App = b.App()
    watchShutdown(b) // 优雅停止：自订阅 SIGINT/SIGTERM（见下）
    // x-token → Authorization 头映射（rulego 只认 Authorization / ?token=，不认 GVA 的 x-token）
    group.Any(prefix+"/*path", mapXToken(), gin.WrapH(b.Handler()))
    // 显式挂载子路径（rulego 路由已含 BasePath 前缀，勿 StripPrefix）
}

// mapXToken GVA 前端统一携带 x-token（web/src/utils/request.js），rulego 的
// extractAuthorization 只读标准 Authorization 头或 ?token= query。此处补映射，前端零改动。
func mapXToken() gin.HandlerFunc {
    return func(c *gin.Context) {
        if c.GetHeader("Authorization") == "" {
            if t := c.GetHeader("x-token"); t != "" {
                c.Request.Header.Set("Authorization", "Bearer "+t)
            }
        }
        c.Next()
    }
}

// watchShutdown GVA v2 插件接口无 Stop 钩子、core/server_run.go 优雅退出只调 srv.Shutdown，
// 胶水层自订阅退出信号关闭 rulego App（signal.Notify 支持多订阅者，与 initServer 并存安全）。
func watchShutdown(b *bridge.Bridge) {
    ch := make(chan os.Signal, 1)
    signal.Notify(ch, syscall.SIGINT, syscall.SIGTERM)
    go func() {
        <-ch
        if err := b.Stop(); err != nil {
            global.GVA_LOG.Error("rulego App 停止异常", zap.Error(err))
        }
    }()
}
```

> 旧骨架中 `func (p *plugin) Stop()` 已删除——v2 Plugin 接口只有 `Register`，该 Stop 方法不会被任何框架代码调用（评审实测确认），生命周期统一走上面的 `watchShutdown`。

并在 `server/plugin/register.go` 增加空导入激活：

```go
_ "github.com/flipped-aurora/gin-vue-admin/server/plugin/rulego"
```

## M3 认证统一（约 1 天）

### 3.1 关闭自带认证 + 桥接 GVA 身份

```go
bridge.New(
    bridge.WithAppOptions(
        app.WithConfig(cfg),                        // require_auth=true（M2 已设）
        app.WithModules(bootstrap.DefaultModules()...),
        app.WithAuthenticator(&gvaAuthenticator{}), // 用 GVA JWT 校验（utils.NewJWT().ParseToken）
        app.WithAuthorizer(&gvaAuthorizer{}),       // resource/action → 虚拟路径 → GVA Casbin
    ),
    bridge.WithoutLocalAuth(),                      // 彻底关闭 rulego /login、/users*
    bridge.WithResponseWrapper(gvaEnvelope),
)
```

要点（评审修订，SPI 签名以 v0.37.2 实测为准，完整代码见 01 文档 §4.6）：

1. `gvaAuthenticator`：**SPI 签名是 `Authenticate(authorization string)`，入参为 Authorization 头原始值（`Bearer xxx`），拿不到 `*http.Request`**——不能在此读 `x-token`；`x-token → Authorization` 映射已由 M2 的 `mapXToken()` 中间件在更外层完成。实现：剥 `Bearer ` 前缀 → `utils.NewJWT().ParseToken()`（直接复用 GVA `utils/jwt.go`）→ 组装 `model.UserContext{Username, Roles: [AuthorityId 字符串]}`，失败返回 error（rulego 自动回 401）；
2. `gvaAuthorizer`：**SPI 签名是 `Authorize(user, resource, action)`，入参是语义标签（如 `rule`/`write`），不是 HTTP path/method**——不能直接套 GVA Casbin 的 (path, method) 策略。按 01 文档 §4.6 的静态映射表把 `resource/action` 翻译为虚拟路径（如 `rule`/`write` → POST `/rulego/rule`），再调 `utils.GetCasbin().Enforce(角色ID字符串, 虚拟路径, 虚拟方法)`（与 `middleware/casbin_rbac.go` 同一入口）；**映射表外的未知组合一律拒绝**；
3. 授权数据：虚拟路径（`/rulego/rule`、`/rulego/component`、`/rulego/config` 等约 7 条）走 GVA 后台「API 管理」录入 + 角色授权，超级管理员沿用既有 888 策略；
4. GVA 前端请求 `@/utils/request.js` 已统一携带 `x-token`（request.js:146），经 M2 中间件映射后 `/rulego/**` 走同一套身份体系，前端零改动；WebSocket 调试端点用 `?token=` query（rulego 原生支持）。

## 官方版本升级 SOP（Git 专家视角）

### 日常升级（官方发布新 release 时）

```bash
# 1. 确认官方新 tag（Gitee / GitHub 任一）
git ls-remote --tags https://gitee.com/rulego/rulego.git | awk -F/ '{print $NF}' | grep -v '\^{}' | sort -V | tail -3

# 2. GVA 仓库 subtree 拉取新版（--squash 保持子树历史为单点）
cd /home/changdq/src/github/changdongqing/gin-vue-admin
git subtree pull --prefix=server/rulego \
    https://gitee.com/rulego/rulego.git v0.38.0 --squash
# 拉取前建议先在独立分支演练，通过后再合入 main

# 3. 解决冲突（如有）→ go mod tidy → 全量构建 → 回归
cd server && go mod tidy && go build ./... && go test ./...
```

### 升级注意事项

- 关注官方新版本的 **go 指令**是否抬升（当前 1.25.0）、`server/go.mod` 依赖是否引入重大变化；
- **复查共享依赖版本**（评审新增）：对照 01 文档 §4.4 共享依赖表，重点盯 `mcp-go`/`goja`/`jwt/v5` 的新版本要求——凡 `mcp-go` 变动，必跑 GVA `server/mcp/` 功能回归；
- 升级后必跑 M3 认证三态回归（401/200/403）与映射表单元测试，确认 bridge 扩展点 API 未变（尤其 `Authenticator.Authenticate(authorization string)` / `Authorizer.Authorize(user, resource, action)` 签名与 resource/action 枚举值——枚举有增减时同步更新 §4.6 映射表）；
- 官方 components 生态版本组合变化时整体验证（`go mod tidy` + 冒烟）。

### 冲突处理原则

- `server/rulego/` 内冲突以上游为准（树内只读纪律的前提）；
- 胶水层 `server/plugin/rulego/` 与上游无关，不参与冲突；
- 若曾违规在树内打补丁：按 `GVA-PATCHES.md` 登记逐个重放到新版本上，或向官方仓库提 PR。

### 紧急回滚

```bash
git revert <subtree-merge-commit>        # 回滚某次 subtree pull
# 或回退到上一基线 tag：
git subtree pull --prefix=server/rulego https://gitee.com/rulego/rulego.git v0.37.2 --squash
```

### 为什么不是 submodule（备选记录）

若日后切换 submodule：`.gitmodules` 指向官方仓库，`replace` 路径指向 submodule 工作区路径；CI 与所有开发者必须 `git submodule update --init`。代价是构建前置步骤 + 忘 init 的失败排查成本，故仅作备选。
