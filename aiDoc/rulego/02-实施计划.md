## M2 桥接运行（约 1 天）

### 2.1 胶水插件骨架

`server/plugin/rulego/plugin.go`（沿用 GVA 插件形态，示例骨架，字段以实际 API 为准）：

```go
package rulego

import (
    "github.com/gin-gonic/gin"
    "github.com/rulego/rulego/server/app"
    "github.com/rulego/rulego/server/bootstrap"
    "github.com/rulego/rulego/server/bridge"
)

const prefix = "/rulego"

var App *app.App

type plugin struct{}

var Plugin = new(plugin)

func (p *plugin) Register(group *gin.Engine) {
    cfg := loadConfig() // 读取 server/resource/rulego/config.conf（或 gva config 中 rulego 段）
    b, err := bridge.New(
        bridge.WithAppOptions(
            app.WithConfig(cfg),                              // BasePath: "/rulego"
            app.WithModules(bootstrap.DefaultModules()...),
            // M3 追加: app.WithAuthenticator / app.WithAuthorizer
        ),
        // M3 追加: bridge.WithoutLocalAuth(),
        bridge.WithResponseWrapper(gvaEnvelope),              // 统一 {code,data,msg} 信封
    )
    if err != nil {
        panic("rulego bridge init: " + err.Error())
    }
    App = b.App()
    // 显式挂载子路径（rulego 路由已含 BasePath 前缀，勿 StripPrefix）
    group.Any(prefix+"/*path", gin.WrapH(b.Handler()))
}

func (p *plugin) Stop() { _ = App.Stop() }
```

并在 `server/plugin/register.go` 增加空导入激活：

```go
_ "github.com/flipped-aurora/gin-vue-admin/server/plugin/rulego"
```

### 2.2 配置落位

- 复制 `server/rulego/server/config.conf` → `server/resource/rulego/config.conf`（纳入 GVA 配置资产），filestore 数据目录指向 `./resource/rulego/data`（随部署卷持久化）；

## M3 认证统一（约 1 天）

### 3.1 关闭自带认证 + 桥接 GVA 身份

```go
bridge.New(
    bridge.WithAppOptions(
        app.WithConfig(cfg),
        app.WithModules(bootstrap.DefaultModules()...),
        app.WithAuthenticator(&gvaAuthenticator{}), // 用 GVA JWT 校验（utils.TokenNext / jwt.Parse）
        app.WithAuthorizer(&gvaAuthorizer{}),       // 用 GVA Casbin 判定（路径→角色→策略）
    ),
    bridge.WithoutLocalAuth(),                      // 彻底关闭 rulego /login、/users*
    bridge.WithResponseWrapper(gvaEnvelope),
)
```

要点：

1. `gvaAuthenticator`：从请求头 `x-token` 解析 GVA JWT Claims，校验通过则向 rulego 传递用户身份（用户 ID/角色），失败返回 401；
2. `gvaAuthorizer`：将 `/rulego/**` 的访问映射到 GVA Casbin 策略（可新增 `rulego` 相关 API 资源，走 GVA 后台"API 管理"正常录入授权），实现"超级管理员全放行、普通角色按策略"；
3. GVA 前端请求 `@/utils/request.js` 已统一携带 `x-token`，`/rulego/**` 走同一套拦截即可。

### 3.2 M3 验收

- [ ] 无 token 访问 `/rulego/**` → 401（GVA 信封格式）；
- [ ] admin 登录后访问 → 200；
- [ ] 普通角色未授权访问 → 403；
- [ ] rulego 自带 `/login`、`/users*` 端点已 404/关闭。

## M4 深度整合（约 2~3 天，可拆分独立排期）

1. **组件生态按需引入**：按 build tag 模式自建 `with_ai.go`/`with_iot.go` 等（参考 `server/rulego/server/cmd/server/with_*.go`），CI 默认只编基础组件；
2. **Docker**：`server/Dockerfile` 固定 `golang:1.25-alpine`；docker-compose 的 gva-server 挂载 `resource/rulego/` 数据卷；
3. **CI**：go 版本抬到 1.25；新增"`server/rulego/` 树内 diff 检查"（第三方只读纪律）；
4. **前端（GVA 自建）**：GVA 前端新增"规则链管理"页面（Vue3 + Element Plus），REST 走 `/rulego/**`，风格与既有 GVA 页面一致（表格可用 GvaGrid）；webui-vben 已舍弃，不做替代性部署；
5. **存储演进（可选）**：实现 `store.StoreProvider` 把规则链元数据落到 GVA 的 PostgreSQL（gin_vue_admin 库新增 schema/表），与 GVA 数据生命周期统一。

## 官方版本升级 SOP（Git 专家视角）

### 日常升级（官方发布新 release 时）

```bash
# 1. 确认官方新 tag（Gitee / GitHub 任一）
git ls-remote --tags https://gitee.com/rulego/rulego.git | awk -F/ '{print $NF}' | grep -v '\^{}' | sort -V | tail -3

# 2. GVA 仓库 subtree 拉取新版（--squash 保持子树历史为单点）
cd /home/changdq/src/github/changdongqing/gin-vue-admin
git subtree pull --prefix=server/rulego \
    https://gitee.com/rulego/rulego.git v0.38.0 --squash
# 拉取前建议先在独立分支演练，通过后再合入 main

# 3. 解决冲突（如有）→ go mod tidy → 全量构建 → 回归
cd server && go mod tidy && go build ./... && go test ./...
```

### 升级注意事项

- 关注官方新版本的 **go 指令**是否抬升（当前 1.25.0）、`server/go.mod` 依赖是否引入重大变化；
- 升级后必跑 M3 认证三态回归（401/200/403），确认 bridge 扩展点 API 未变；
- 官方 components 生态版本组合变化时整体验证（`go mod tidy` + 冒烟）。

### 冲突处理原则

- `server/rulego/` 内冲突以上游为准（树内只读纪律的前提）；
- 胶水层 `server/plugin/rulego/` 与上游无关，不参与冲突；
- 若曾违规在树内打补丁：按 `GVA-PATCHES.md` 登记逐个重放到新版本上，或向官方仓库提 PR。

### 紧急回滚

```bash
git revert <subtree-merge-commit>        # 回滚某次 subtree pull
# 或回退到上一基线 tag：
git subtree pull --prefix=server/rulego https://gitee.com/rulego/rulego.git v0.37.2 --squash
```

### 为什么不是 submodule（备选记录）

若日后切换 submodule：`.gitmodules` 指向官方仓库，`replace` 路径指向 submodule 工作区路径；CI 与所有开发者必须 `git submodule update --init`。代价是构建前置步骤 + 忘 init 的失败排查成本，故仅作备选。
