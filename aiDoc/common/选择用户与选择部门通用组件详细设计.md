## 一、功能概述

### 1.1 功能定位

为全系统提供「选择用户」「选择部门」的**通用前端底座组件**，统一三类复用场景：

1. **普通表单**：el-form 内作为表单项（抽屉/对话框表单）；
2. **gvaGrid 查询项与单元格**：表格上方筛选区的查询项、列表列的显示渲染（及未来的行内编辑态）；
3. **独立嵌入**：业务自己的弹窗/工作流面板直接引用弹窗内芯。

组件不承载任何业务语义（不关联审批、不触发权限），仅完成「候选人呈现 + 选中值收发 + 回显」。

### 1.2 形态最终裁定（讨论结论固化）

| 组件 | 形态 | 裁定理由 |
|---|---|---|
| **GvaChooseDept**（部门） | **单一形态：el-tree-select 下拉面板** | 部门量级小（几百节点内）、树形浏览即定位方式；el-tree-select 原生覆盖 filterable / multiple tags / check-strictly（任意层级）；弹窗纯属过度设计 |
| **GvaChooseUser**（用户） | **双形态，`mode` prop 切换**：`select`（默认）+ `dialog` | 纯下拉应对日常表单/单元格（几百人量级，全量缓存 + 前端过滤）；弹窗形态承载「按部门 + 按岗位浏览、批量勾选」场景（依赖已落地的岗位管理模块） |
| **GvaChooseUserDialog**（弹窗内芯） | 独立导出 | 既被 GvaChooseUser 的 `mode="dialog"` 复用，也可被任何 `el-dialog` 直接嵌入 |

**明确弃用**（讨论中的反面清单，防止实现时回潮）：

- 级联下拉式：多选与任意层级体验差，tree-select 已全覆盖；
- 自绘 popover 面板：键盘导航/滚动容器定位/虚拟滚动需自研，维护成本高；
- 弹窗作为唯一形态：表格单元格录入与嵌套弹窗场景过重；
- 抽 user.vue 编辑抽屉改造：旧耦合（authority/department 混杂）拖累通用性。

### 1.3 功能范围

**含**：

1. GvaChooseDept：部门下拉树（单/多选、任意层级/仅叶子、前端过滤、companyId 静态裁剪）；
2. GvaChooseUser select 形态：用户下拉（单/多选 tags、前端关键字过滤、params 静态过滤）；
3. GvaChooseUser dialog 形态：部门树（任意层级）+ 岗位多选 + 关键字三维过滤、勾选、已选标签、全量覆盖确认；
4. 数据层 cache.js：用户/部门/岗位模块级缓存 + 解析/过滤工具；
5. gvaGrid 渲染器 4 个（单元格显示 ×2 + 查询项 ×2）；
6. 后端新增 1 个只读轻量接口 `/user/getUserSimpleList`（**无数据库变更、无迁移、无 AutoMigrate**）。

**不含**：

- 拼音首字母检索（可选增强，引入 pinyin-pro 时再加，不影响接口）；
- 数据权限掺入（见 §10-2 决策记录）；
- 既有页面改造（user.vue / apiToken / post.vue 分配员工抽屉**本期不动**，渐进迁移列为后续，避免回归）；
- 部门选择器弹窗形态。

## 三、数据层设计（cache.js）

### 3.1 缓存结构

位置：`web/src/components/choose/cache.js`。范式照抄 `gvaGrid/renderers.js` 的 dictCache（模块级 `reactive`，异步加载完成后依赖它的渲染自动更新——这正是单元格显示与回显能"先渲染后到位"的机制基础）。

```javascript
const CACHE_TTL = 5 * 60 * 1000 // 5 分钟

const state = reactive({
  users: [],        // UserSimple[]（见 §4.2）
  userMap: {},      // id -> UserSimple
  departments: [],  // 平铺 SysDepartment[]（含 children 树由调用方组装或缓存层组装 deptTree）
  deptMap: {},      // id -> SysDepartment
  deptTree: [],     // 树形（getDepartmentList 原样）
  posts: [],        // 启用岗位 SysPost[]（getPostListAll）
  loadedAt: { users: 0, departments: 0, posts: 0 },
  inflight: {}      // 进行中的 Promise（单飞：并发调用只发一次请求）
})

export function ensureUsers(force = false)  // TTL 内直接复用；force 供弹窗打开时强刷
export function ensureDepts(force = false)
export function ensurePosts(force = false)
```

要点：

1. **单飞（inflight 去重）**：多个组件同屏首次渲染时只发一次请求；
2. **强刷时机**：dialog 形态每次打开 `ensureUsers(true)` 静默刷新（人员调动尽快可见），select 形态遵循 TTL；
3. 缓存无失效推送——新鲜度取舍见 §10-1。

### 3.2 过滤与解析工具（同文件导出）

```javascript
// 用户三维过滤（dialog 与 select 的 params 过滤共用）
filterUsers({ keyword, departmentId, postIds }) {
  // keyword: 命中 nickName 或 userName（不分大小写 includes）
  // departmentId: 子树过滤——deptDescendantIds(departmentId) 集合内
  // postIds: 交集非空（多选岗位为并集语义：命中任一即可）
}

// 部门后代集合（含自身）：利用物化路径 parentIds "0,1,3," 的 token 匹配，
// 与后端 GetDepartmentSubTreeIds 语义对齐
deptDescendantIds(departmentId)

// ID → 显示名（单元格渲染、纯显示场景用；未命中返回 ''）
resolveUserLabel(id)   // `${nickName}（${userName}）`，nickName 空则回退 userName
resolveDeptLabel(id)   // 部门 name

// 岗位名解析（dialog 用户行内岗位 tag 显示）
resolvePostLabels(postIds)
```

### 3.3 值与回显协议（全局约定）

- **v-model 绑 ID**：单选 `number`，多选 `number[]`（随 `multiple` 切换，切换由调用方自行清值，见 §10-5）；
- `change` 事件第二参返回**完整行对象**（`rows: UserSimple[]`），调用方需要昵称/部门时不必反查；
- **回显时序**：编辑态打开时缓存可能未就绪——select 形态对未知 ID 先显示 ID 本身、reactive 缓存到位后自动更正为姓名（dictCache 同款体验）；这是全量缓存方案下唯一需接受的时序现象。

## 四、后端设计（getUserSimpleList）

### 4.1 路由与鉴权（关键设计）

现有两个路由组的边界（已核对 `initialize/router.go:67-70`）：

| 组 | 中间件 | 语义 |
|---|---|---|
| PublicGroup | 无 | 登录/初始化（**不能放**——用户名单裸奔） |
| PrivateGroup | JWTAuth + CasbinHandler | 逐角色授权（**不能放**——每个使用选择器的业务角色都得授 `getUserList` 类权限，通用组件开箱即用即破产） |

**裁定：新增第三个路由组 `JwtOnlyGroup`（仅 JWTAuth）**，登录即可用、不配 casbin。理由：选人/选部门是协作语义，任何登录角色都有权看到同事的昵称/用户名/部门/岗位；接口不含手机号、邮箱等敏感字段（字段白名单见 §4.2），泄露面可控。升级路径见 §10-3。

```go
// server/initialize/router.go（PrivateGroup 定义之后）
JwtOnlyGroup := Router.Group(global.GVA_CONFIG.System.RouterPrefix)
JwtOnlyGroup.Use(middleware.JWTAuth())
...
systemRouter.InitUserSimpleRouter(JwtOnlyGroup) // 通用选择器数据（登录即可，不走 casbin）
```

```go
// server/router/system/sys_user.go 新增（独立方法，不动 InitUserRouter 签名）
func (s *UserRouter) InitUserSimpleRouter(Router *gin.RouterGroup) {
	userSimpleRouter := Router.Group("user")
	userSimpleRouter.GET("getUserSimpleList", baseApi.GetUserSimpleList) // 只读高频，不挂 OperationRecord
}
```

### 4.2 接口定义

| 项 | 值 |
|---|---|
| 路由 | `GET /user/getUserSimpleList` |
| 鉴权 | JWT（登录即可） |
| 入参 | 无（全量返回，几百~几千人无分页；扩展预案见 §10-4） |
| 出参 | `{code, data: {list: []UserSimple}, msg}` |

```go
// server/model/system/response/sys_user.go 追加（与 SysUserResponse 同文件）
type UserSimple struct {
	ID             uint   `json:"ID"`
	UserName       string `json:"userName"`
	NickName       string `json:"nickName"`
	DepartmentId   uint   `json:"departmentId"`
	DepartmentName string `json:"departmentName"`
	PostIds        []uint `json:"postIds"`
}
```

**字段白名单即安全边界**：无手机号/邮箱/密码字段残迹/originSetting；`enable=2`（冻结）用户**不返回**（冻结用户不可被协作指派）。

### 4.3 Service 实现（范式）

```go
// server/service/system/sys_user.go 追加
// GetUserSimpleList 通用选择器用户全量（未软删 + 未冻结，含部门名与岗位ID）
func (userService *UserService) GetUserSimpleList() (list []response.UserSimple, err error) {
	// 1) 主查询：两表联查取白名单字段（范式同 post 模块 GetPostUsers）
	err = global.GVA_DB.Table("sys_users u").
		Select("u.id, u.username, u.nick_name, u.department_id, d.name AS department_name").
		Joins("LEFT JOIN sys_departments d ON d.id = u.department_id AND d.deleted_at IS NULL").
		Where("u.deleted_at IS NULL AND u.enable = 1").
		Order("u.id").
		Scan(&list).Error
	if err != nil {
		return
	}
	// 2) 岗位聚合：sys_user_post 一次全量（硬删表无软删条件；几百~几千行内存分组，无 N+1）
	var rows []system.SysUserPost
	if err = global.GVA_DB.Find(&rows).Error; err != nil {
		return
	}
	m := make(map[uint][]uint, len(rows))
	for _, r := range rows {
		m[r.UserId] = append(m[r.UserId], r.PostId)
	}
	for i := range list {
		list[i].PostIds = m[list[i].ID]
	}
	return
}
```

注：关联表中指向已删/已冻结用户的冗余行会在"按 list 装配"时自然丢弃（DeleteUser 已清理关联，此处仅防御历史脏数据）。

API 层 handler 加在 `BaseApi`（用户域 handler 既有归属，`sys_user.go` api 文件），范式与 `GetUserList` 一致（ShouldBind 无、直接调 service、`OkWithDetailed(gin.H{"list": ...})`）。

### 5.2 GvaChooseDept

| Props | 类型/默认 | 说明 |
|---|---|---|
| v-model | `number \| number[]` | 随 multiple 切换 |
| multiple | `false` | 多选（tags 展示） |
| checkStrictly | `true` | **任意层级可选**（讨论裁定默认值）；`false` 收紧为仅叶子 |
| params | `{ companyId? }` | 静态裁剪：缓存内按 companyId 过滤并保留祖先链 |
| disabled / placeholder / clearable / size | — | 透传 el-tree-select |

实现要点：

1. 封装 `el-tree-select`，`node-key="ID"`、`:props="{ label: 'name', children: 'children' }"`、`check-strictly` 透传、`filterable`（前端过滤）、`default-expand-all` + `:render-after-expand="false"`（与 user.vue/department.vue 现有用法一致）；
2. `status === 2` 的部门节点置 `disabled: true`——**可见但不可选**，保证历史值回显不丢（同岗位选择器对停用岗位的处理）；
3. 数据来自 `ensureDepts()`，组件内 `computed` 从 reactive 缓存取树，缓存到位自动展开渲染；
4. Emits：`change(value, rows)`（rows 为完整 SysDepartment 节点）；Expose：`refresh()`。

### 5.3 GvaChooseUser

| Props | 类型/默认 | 说明 |
|---|---|---|
| v-model | `number \| number[]` | 随 multiple 切换 |
| multiple | `false` | 多选 tags |
| mode | `'select'` | `select`：下拉；`dialog`：输入框触发 + 弹窗（§5.4） |
| params | `{ departmentId?, postId? }` | select 形态：候选在缓存内预过滤；dialog 形态：作为初始过滤条件 |
| disabled / placeholder / clearable / size | — | 透传 |

**select 形态实现要点**：

1. `el-select` + `filterable`，候选 = `filterUsers(params)`（全量缓存前端过滤，几百人无性能问题）；
2. 选项 label：`${nickName}（${userName}）`；多选 tags 原生；
3. 回显：modelValue 中的 ID 若不在缓存（未就绪），先渲染 ID 本身，reactive 到位后自动更正（§3.3）；
4. 候选不含冻结用户（后端已过滤）；
5. Emits：`change(value, rows)`（rows: UserSimple[]）；Expose：`refresh()`。

**dialog 形态**：只读触发器（回显已选 tags + clearable 清空）+ 点击打开 GvaChooseUserDialog（append-to-body，规避表单在 drawer/dialog 内的嵌套问题）。

### 5.4 GvaChooseUserDialog（弹窗内芯）

布局（交互范式取自 post.vue 分配员工抽屉的成熟实现，改为全前端过滤）：

```
┌──────────────────────────────────────────────────┐
│ 选择用户                              [取消] [确定] │
│ ┌────────────┐  [关键字输入框____]  [岗位多选下拉 ▼] │
│ │ 部门树       │  ┌──────────────────────────────┐ │
│ │ (任意层级,   │  │ ☑ 张三   技术一部   [项目经理] │ │
│ │  单选高亮)   │  │ ☐ 李四   技术二部   [测试工程师]│ │
│ │ ● 全部部门   │  │ ...（不分页，整表滚动）        │ │
│ │ ├ 技术部     │  └──────────────────────────────┘ │
│ │ └ 市场部     │                                    │
│ └────────────┘                                     │
│ 已选（3）：张三 × ｜ 王五 × ｜ 赵六 ×                 │
└──────────────────────────────────────────────────┘
```

交互流：

1. **打开**：`ensureUsers(true)` 静默强刷 + `ensurePosts()`（岗位筛选项与行内 tag）；初始已选由 modelValue 经 `userMap` 装配进 `selectedMap`；
2. **三维过滤全部前端计算**（`filterUsers`）：部门树点选（任意层级，含子部门）、岗位多选（并集语义）、关键字（nickName/userName）；组合为 AND；
3. **勾选跨过滤保持**：`selectedMap`（ID → UserSimple）为唯一事实源，过滤条件切换/清空不丢已选；已选标签可单独 × 移除；
4. **确定**：emit `change(value, rows)` 并关闭（value 即最终态）；取消不改动 modelValue；
5. 表格不分页（几百行 el-table 可承受）；超千行再引入前端分页/虚拟滚动，**接口与组件 API 均不变**（§10-4）。

## 六、gvaGrid 渲染器注册

在 `web/src/components/gvaGrid/renderers.js` 注册 4 个渲染器（命名对齐 gvaDict / gvaDictSelect 既有范式：单元格与查询项**分名注册**）：

| 渲染器名 | 钩子 | 行为 |
|---|---|---|
| `gvaChooseUser` | renderTableDefault | 值为 ID 或 ID 数组 → 单值渲染名称文本、数组渲染 el-tag 列表；名称来自 reactive 缓存，未就绪显示原值、到位自动重渲染 |
| `gvaChooseUserSelect` | renderFormItemContent + formItemResetMethod | 渲染 GvaChooseUser（v-model 绑 `data[field]`，props 透传 multiple/mode/params/placeholder）；重置钩子按 multiple 置 `[]` / `undefined` |
| `gvaChooseDept` | renderTableDefault | 同上，部门名 |
| `gvaChooseDeptSelect` | renderFormItemContent + formItemResetMethod | 渲染 GvaChooseDept |

```javascript
// renderers.js 范式（gvaDictSelect 同款骨架）
import GvaChooseUser from '@/components/choose/chooseUser.vue'
import GvaChooseDept from '@/components/choose/chooseDept.vue'
import { resolveUserLabel, resolveDeptLabel, ensureUsers, ensureDepts } from '@/components/choose/cache'

VxeUI.renderer.add('gvaChooseUserSelect', {
  renderFormItemContent(renderOpts, { data, field }) {
    const props = renderOpts.props || {}
    return [h(GvaChooseUser, {
      modelValue: data[field],
      'onUpdate:modelValue': (v) => { data[field] = v },
      multiple: props.multiple,
      mode: props.mode,
      params: props.params,
      placeholder: props.placeholder || '请选择用户',
      clearable: props.clearable !== false
    })]
  },
  formItemResetMethod({ data, field }) {
    data[field] = /* multiple ? */ [] /* : undefined */  // 按 props.multiple 分支
  }
})
```

缓存副作用：单元格渲染器首次渲染时调用 `ensureUsers()` / `ensureDepts()`（幂等单飞），此后所有消费方共享。

## 十、风险与注意事项

1. **缓存新鲜度**：select/单元格场景最长滞后 TTL（5 分钟）+ 会话内无推送。缓解：dialog 打开强制刷新、组件 expose `refresh()`、TTL 可调；接受权衡（几百人规模下选错人的概率与影响均低）；
2. **数据权限不掺入（决策记录）**：simpleList 不走 `DataScopeService` 过滤——选人是协作语义而非数据可见性语义，若掺入会静默收缩候选造成"找不到人"。若未来某场景需要受限候选（如仅本部门可指派），用 `params` 业务侧传入，或后续加 `scope` 变体接口，不动本组件；
3. **JWT-only 安全边界**：任何登录用户可见全体同事昵称/用户名/部门/岗位（无手机/邮箱）。字段白名单是硬约束，后续加字段需过安全评审；如需收紧，迁移 PrivateGroup + 全角色 casbin 授权（组件与缓存零改动，仅路由挂载与授权运营变化）；
4. **量级扩展路径**（几百人设计上限）：用户破千——dialog 加前端分页；破万——simpleList 改分页/瘦身 + select 形态切 `el-select-v2` 虚拟列表 + 岗位聚合改后端 SQL；三处演进均不破坏组件对外 API（v-model/change 协议不变）；
5. **multiple 切换不清值**：`number ↔ number[]` 类型随 multiple 变化，调用方切换 multiple 时必须自行清空 v-model（文档化约定，组件不做隐式转换）；
6. **sys_user_post 脏数据防御**：指向不存在用户的关联行在装配 postIds 时自然丢弃（§4.3 注），无需清洗任务；
7. **既有页面渐进迁移**：user.vue 编辑抽屉、apiToken 选用户、post.vue 分配员工抽屉可后续替换为本组件族（后者即 `mode="dialog"` 的直接等价物），**本期一律不动**，避免功能回归；替换时注意 post.vue 抽屉的数据权限语义差异（getUserList 带 DataScope，本组件不带，见第 2 条）；
8. **sys_apis 盘点口径**：接口不在 PrivateGroup，casbin 对其无效；若运维在角色 API 管理中勾选它不会产生任何放行/拦截变化，描述中注明"JWT 登录即可"避免误配置预期。
