## 3. 数据权限引擎（service/system/sys_data_scope.go）

### 3.1 数据范围常量

```go
const (
    DataScopeAll          = 1 // 全部数据
    DataScopeCustom       = 2 // 自定义（明细见 sys_authority_data_scopes）
    DataScopeCompany      = 3 // 本公司
    DataScopeDeptChildren = 4 // 本部门及以下
    DataScopeDept         = 5 // 本部门
    DataScopeSelf         = 6 // 仅本人
)
```

### 3.2 解析结果

```go
// UserScope 用户数据权限解析结果
type UserScope struct {
    All     bool   // 全部数据（多角色任一为"全部"即 true）
    UserId  uint   // 当前用户
    DeptIds []uint // 机构范围展开后的部门 ID 集合（含公司展开、部门子树展开）
}

// HasFilter 是否需要过滤（All=false 时调用方必须追加条件）
func (u *UserScope) HasFilter() bool { return !u.All }
```

### 3.3 解析流程 `ResolveUserScope(userId uint) (*UserScope, error)`

1. 查用户主属部门：`SELECT department_id FROM sys_users WHERE id = ?`。
2. 查用户全部角色及其 `data_scope`：`sys_user_authority` join `sys_authorities`（去重）。
3. **多角色并集合并**（就宽原则）：
   - 任一角色 `=1` → `All=true`，返回。
   - 收集各角色范围展开的部门 ID 集合：
     - `2 自定义`：查明细，`scope_type=company` → 该公司全部部门 ID；`scope_type=department` → `id IN (SELECT id FROM sys_departments WHERE parent_ids LIKE 自身路径% OR id=自身)` 子树。
     - `3 本公司`：主属部门 → `company_id` → 该公司全部部门。
     - `4 本部门及以下`：主属部门子树（物化路径前缀 LIKE）。
     - `5 本部门`：仅主属部门。
     - `6 仅本人`：不贡献部门 ID（本人条件由 userCol 兜底）。
   - 全部去重后得到 `DeptIds`。
4. **退化规则**：用户无主属部门时，范围 2/3/4/5 展开为空 → `DeptIds` 为空 → 查询退化为"仅本人"，宁紧勿松。
5. 开关：`global.GVA_CONFIG.System.DataPermission.Enable == false` 时直接返回 `All=true`（总开关旁路）。

### 3.4 gorm Scope 接入

```go
// Scope 返回可直接用于 db.Scopes(...) 的查询作用域
// deptCol: 业务表部门列名，如 "dept_id"；userCol: "仅本人"判定列，如 "create_user_id"，可为空
func (s *DataScopeService) Scope(userId uint, deptCol, userCol string) func(*gorm.DB) *gorm.DB
```

生成条件语义：

| 解析结果 | 生成 SQL |
| --- | --- |
| `All=true` | 不追加任何条件 |
| `DeptIds` 非空 且 userCol 非空 | `(dept_col IN (...) OR user_col = userId)` |
| `DeptIds` 非空 且 userCol 为空 | `dept_col IN (...)` |
| `DeptIds` 为空 且 userCol 非空 | `user_col = userId`（含"仅本人"档、无部门退化） |
| `DeptIds` 为空 且 userCol 为空 | `1 <> 1`（fail-close，查不到任何行） |
| 解析出错（DB 异常等） | `1 <> 1` + ERROR 日志（**失败关闭**） |

> 设计取舍：本人创建/本人相关的行始终可见（`OR user_col = userId`），避免"自己提交的数据自己看不见"的体验问题；若某业务要求严格机构隔离，调用方可传 `userCol=""`。

### 3.5 典型接入（本期内置）

用户管理列表 `GetUserInfoList`：

```go
// service/system/sys_user.go GetUserInfoList 内
if global.GVA_CONFIG.System.DataPermission.Enable {
    db = db.Scopes(DataScopeServiceApp.Scope(userId, "department_id", "id"))
}
```

- `deptCol = "department_id"`（用户表自身的部门列）
- `userCol = "id"`（"仅本人"= 只能看到自己这条用户记录）

## 4. 公司/部门服务设计

### 4.1 树查询

`GetCompanyTree()`：全表 `ORDER BY sort, id` 一次取出 → 内存建树（map[parent]children）→ 返回森林。部门树 `GetDepartmentTree(companyId uint, name string)` 支持按公司（取该公司全部部门再建树）与名称（`LIKE` 匹配返回平铺行，无树）筛选。

### 4.2 物化路径维护

- 创建：`parentIds = 父.parentIds + 父.ID + ","`，`treeLevel = 父.treeLevel + 1`。
- 更新（父变动）：校验"不能把自己挂到自己子孙下"（目标父的 `parent_ids` 前缀包含自身路径则拒绝）→ 重算自身 → 批量改子孙：`UPDATE ... SET parent_ids = 新自身路径 || substring(parent_ids from length(旧自身路径)+1), tree_level = tree_level ± delta WHERE parent_ids LIKE '旧自身路径%'`。
- 删除保护：
  - 公司：存在子公司或挂靠部门 → 拒绝（`请先删除/转移其下子公司与部门`）。
  - 部门：存在子部门或用户 → 拒绝。
- 编码唯一：创建/更新时查重（软删除外）。

### 4.3 部门挂靠公司

创建/更新部门必须携带合法 `companyId`；公司停用/删除前的保护见上；页面切换公司即切换部门树。

## 5. 数据范围配置服务

```go
// service/system/sys_authority_data_scope.go
SetAuthorityDataScope(authorityId uint, dataScope int, companyIds, departmentIds []uint) error
GetAuthorityDataScope(authorityId uint) (dataScope int, companyIds, departmentIds []uint, err error)
```

- `Set`：事务内——更新 `sys_authorities.data_scope`；全删后重插明细（scope_type=company → companyIds，department → departmentIds）。仅当 `dataScope=2` 时保留明细，其他档位清空明细。
- `Get`：读档位 + 明细分组返回。
- 复制角色 `CopyAuthority` 时同步复制 `data_scope` 与明细（明细用新角色 ID 重插）。

## 7. 种子数据（initialize/data_permission.go）

启动时（`RegisterTables` 之后）幂等执行，受 `data-permission.seed`（默认 true）控制：

1. **菜单**（`sys_base_menus`）：在「超级管理员」目录（parent=superAdmin）下追加「公司管理」「部门管理」两页（component 指向 `view/superAdmin/company/company.vue`、`view/superAdmin/department/department.vue`），按 `(parent_id, name)` 查重。
2. **角色菜单**（`sys_authority_menus`）：给 888（admin）关联新菜单。
3. **API**（`sys_apis`）：登记 6.1/6.2/6.3 全部接口，按 `(path, method)` 查重。
4. **casbin**（`casbin_rule`）：为 888 插入 `p` 规则；插完调用 `CasbinServiceApp.FreshCasbin()` 热加载。
5. **演示组织**（受 `data-permission.seed-demo` 单独控制，默认 true，仅当公司表为空）：一家集团 + 两个子公司 + 若干部门，便于开箱体验；不修改任何存量用户。

## 9. 安全考量

1. **默认放行存量**：新列默认 1（全部），避免升级即锁库。
2. **失败关闭**：引擎异常时返回空结果而非全量。
3. **越权面**：数据范围配置 API 本身仍受 casbin 控制（只有被授予该 API 的角色可改配置）；建议生产环境仅超管角色持有 `/authority/setDataScope`。
4. **删除保护**：组织节点删除前强制检查子孙/挂靠，防止悬空引用导致权限计算错误。
5. **软删兼容**：部门软删后用户的 `department_id` 失效 → 引擎按"无部门"退化仅本人，不会放大权限。
