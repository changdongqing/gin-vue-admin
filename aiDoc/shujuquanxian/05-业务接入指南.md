# 05 业务表接入数据权限指南

数据权限引擎是**显式接入**模式：业务代码在需要受控的查询上追加一个 gorm Scope 即可，不做全局 SQL 魔改。三步完成接入。

## 0. 前置条件

- 公司/部门树已维护（超级管理员 → 公司管理 / 部门管理）
- 用户已分配主属部门（用户管理 → 编辑 → 主属部门）
- 角色已配置数据范围（角色管理 → 设置权限 → 数据权限）
- 引擎开关开启：`system.data-permission.enable: true`（默认）

## 1. 三步接入

### 第一步：业务表加归属列

```go
// 模型增加两个字段（业务已有 create_user_id 类字段可复用，不必重复加）
type BizOrder struct {
    global.GVA_MODEL
    Title        string `json:"title"`
    Amount       float64 `json:"amount"`
    DeptId       uint   `json:"deptId" gorm:"index;comment:数据归属部门"`
    CreateUserId uint   `json:"createUserId" gorm:"index;comment:创建人"`
}
```

> `dept_id`：机构维度过滤列，**必填**；`create_user_id`：「仅本人」档位与"自己数据始终可见"需要，**强烈建议**。

### 第二步：创建数据时填充归属

```go
func (s *BizOrderService) Create(order *BizOrder, userId uint) error {
    // 从当前用户推导归属部门（无部门填 0，仅本人条件兜底）
    deptId, err := DataScopeServiceApp.GetUserDeptId(userId)
    if err != nil {
        return err
    }
    order.DeptId = deptId
    order.CreateUserId = userId
    return global.GVA_DB.Create(order).Error
}
```

### 第三步：查询追加 Scope

```go
func (s *BizOrderService) List(info request.PageInfo, userId uint) (list []BizOrder, total int64, err error) {
    db := global.GVA_DB.Model(&BizOrder{})
    // ★ 一行接入：部门列 + 本人列
    db = db.Scopes(DataScopeServiceApp.Scope(userId, "dept_id", "create_user_id"))

    err = db.Count(&total).Error
    if err != nil {
        return
    }
    err = db.Limit(info.PageSize).Offset((info.Page - 1) * info.PageSize).
        Order("id desc").Find(&list).Error
    return
}
```

API 层取当前用户：`userId := utils.GetUserID(c)`（JWT claims）。

生成 SQL 示例（角色=本部门及以下，用户主属部门 id=5）：

```sql
SELECT * FROM biz_orders
WHERE (dept_id IN (5, 8, 9) OR create_user_id = 1)   -- 引擎追加
ORDER BY id DESC LIMIT 10 OFFSET 0
```

## 2. 引擎行为速查

| 角色数据范围 | 追加条件（deptCol=dept_id, userCol=create_user_id） |
| --- | --- |
| 1 全部数据 | 无（放行） |
| 2 自定义 | `(dept_id IN (勾选公司全部部门 ∪ 勾选部门子树) OR create_user_id = ?)` |
| 3 本公司 | `(dept_id IN (主属部门公司的全部部门) OR create_user_id = ?)` |
| 4 本部门及以下 | `(dept_id IN (主属部门子树) OR create_user_id = ?)` |
| 5 本部门 | `(dept_id IN (主属部门) OR create_user_id = ?)` |
| 6 仅本人 | `create_user_id = ?` |
| （无主属部门） | 退化 `create_user_id = ?` |
| 引擎异常 | `1 <> 1`（失败关闭）+ ERROR 日志 |

多角色：取并集（任一"全部"即放行；部门集合合并）。想严格机构隔离不兜底本人，传 `Scope(userId, "dept_id", "")`。

## 3. 详情/修改/删除接口怎么控？

列表 Scope 只解决"看不见"。防止越权操作单条数据（水平越权），在按 ID 取记录后校验归属：

```go
func (s *BizOrderService) Get(id, userId uint) (order BizOrder, err error) {
    err = global.GVA_DB.Where("id = ?", id).First(&order).Error
    if err != nil {
        return
    }
    // 复用引擎做归属判定
    ok, err := DataScopeServiceApp.CanAccess(userId, "biz_orders", "dept_id", "create_user_id", order.ID)
    if err != nil || !ok {
        return order, errors.New("无权访问该数据")
    }
    return
}
```

`CanAccess` 为引擎提供的单行判定封装（`EXISTS` 同条件子查询），更新/删除接口同理。

## 5. 常见问题

**Q：存量业务表数据 dept_id=0，接入后会不会看不见？**
会（除非角色=全部数据或本人创建）。存量数据刷归属：

```sql
-- 按创建人主属部门回填
UPDATE biz_orders o SET dept_id = COALESCE(u.department_id, 0)
FROM sys_users u WHERE o.create_user_id = u.id;
```

**Q：管理员代录的数据归属谁？**
按创建人（管理员）部门归属。如需"代办归属"，在创建时显式指定 `dept_id`，不要调用 `FillCreate`。

**Q：部门停用影响已有数据吗？**
不影响历史数据可见性判断（引擎不校验部门状态）；停用部门用于禁止新用户/新业务数据挂靠。

**Q：开关关闭后？**
`Scope` 直接放行（不加条件），所有接口回到全局视图。

**Q：性能？**
单次解析 = 3 条主查询（用户、角色、明细）+ 部门子树 LIKE 前缀索引扫描；部门 ID 集合上限通常几百，`IN` 列表可控。若组织规模上万，可在 `ResolveUserScope` 外套缓存（预留点：函数签名稳定，可加内存/Redis 缓存层）。
